# 按键调试与硬件踩坑记录

排查"按键没反应"问题时，从日志读出根因并沉淀的实操记录。

---

## 二脚 vs 三脚微动开关（最常见的坑）

微动开关的引脚数量和内部结构直接决定接法。搞混就会让引脚常低、按键完全没反应。

### 二脚 / 四脚（普通 6×6mm 常见款）

机身上**同一侧的两个脚内部是导通**的，两侧各构成一组端子。等效于普通单刀单掷开关。

```
    ┌──────┐
    │ ▣▣▣  │      同侧两脚内部短接
    │ ▣▣▣  │
    └──────┘
     左组      右组
```

接法：任取左侧一脚接 GPIO，任取右侧一脚接 GND。**怎么插都行。**

### 三脚

引脚排列为 `A | B | C`：

- **A 和 C（两个外侧脚）内部属同一端**
- **B（中间脚）是另一端**

部分型号还带内部指示灯（多一个脚或集成 LED），本质上仍然是"两端子 + 灯"。

**陷阱**：按二脚的思路接线，以为"同侧两脚 = 一端两脚"是对的，
但实际拿到的 A 和 C 是同一个端子 —— 相当于把同一端接到自己身上，
开关永远闭合不到 GND，GPIO 悬空被读成低电平。

**正确接法**：中间脚 B 接一侧，外侧任一脚（A 或 C）接另一侧。

### 为什么症状看起来像固件 bug

引脚常低时，`active_level=0` + 内部上拉的配置会让驱动认为
"这个键从开机就一直按着"：

1. 初始化时电平已经是"按下"，**永远不会有按下边沿**
2. 约 1~2 秒后触发一次 long-press 回调
3. 之后电平不再变化，不再有事件 —— 用户按十几次全无反应

指纹特征：**开机时有一次事件，按压时零事件**。

## 日志判读表

启动时打印每个可疑引脚的电平，一次就能定位问题：

| 启动电平 | 结论 |
|---|---|
| 部分 `1`、部分 `0` | 硬件问题，且只在 `0` 的那几个脚上 |
| 全部 `0` | 全板短路，或上电即被拉低，查面包板 |
| 全部 `1`，按压无变化 | 线接错脚，或开关没导通，用万用表追线 |
| 全部 `1`，回调正常触发 | 固件/配置层面，去查去抖、长按阈值、事件掩码 |

**`1`/`0` 混合是最有信息量的结果** —— 立刻排除固件和 USB/外设占用。

## gpio_get_level() 是诚实探针

外设 claim（占用引脚）**只改写路径**（`gpio_set_level` 的信号路由），
**不改读路径**。所以：

> **如果 `gpio_get_level()` 读到 `0`，引脚就是真的低。**
> "会不会是 USB JTAG 抢了 GPIO19/20"这种猜测，测一下就否掉了。

验证方法：grep 外设的 `.c` 源码找 `gpio`，找不到就是它从未 claim 过引脚。

## 本项目的实际案例

ESP32-C6 + `bread-compact-c6` 板，三个按键（touch GPIO21 / vol+ GPIO20 / vol- GPIO19）全部无效。

诊断固件输出：

```
boot(GPIO9)=1  touch(GPIO21)=0  vol+(GPIO20)=0  vol-(GPIO19)=0
btn_probe: touch GPIO21 is LOW at startup
btn_probe: vol+  GPIO20 is LOW at startup
btn_probe: vol-  GPIO19 is LOW at startup
KEY vol-(GPIO19) LONG press -> mute
KEY vol+(GPIO20) LONG press -> max volume
```

三路常低 + 开机各触发一次长按 = 典型的"引脚被短接/悬空被拉低"。
换成二脚按键后全部正常。

### 排查过程中的两处弯路

1. **先怀疑 USB Serial/JTAG 占用 GPIO19/20** —— 错。
   `CONFIG_USJ_ENABLE_USB_SERIAL_JTAG=y` 确实开着，但驱动源码里没有任何 gpio claim。
2. **看照片判断"GND 和信号插进同一条导轨"** —— 错，方向对但部件判断错了。

**正确顺序**：先看启动基线电平 → 只查那些 `0` 的脚上的**元器件** → 再看接线。

## 面包板导轨短接

同一横排（5 连孔导轨）上的孔**电气相通**。GPIO 线和 GND 线落进同一排就等于短接，
引脚永远读 `0`，跟开关没关系。

避免办法：

- 开关跨中缝插是安全的（两脚在中缝两侧 = 不同排）
- **别让 GND 走公共导轨**，把所有 GND 脚在板外并起来，单独拉一根 GND 到开发板
- 优先点对点杜邦线，不要用导轨串接
- 大电流舵机线束和信号线分开走

## OLED 上电慢（本项目实测）

```
W (2970) OLED WATCH: HIT addr=0x3C @ 400000Hz -> installing driver
I (3140) CompactC6Board: OLED IS LIVE
```

开机前 4 次探测全部 miss，约 **2.9 秒**才握手成功。这不是故障，是 I2C 上电慢。
**"插上电等两秒才亮"是正常的**，不要当成坏了反复排查。

详细处理方式见用户级 skill `esp-peripheral-bringup`。
按键排查的完整方法论见 `esp-gpio-button-triage`。
